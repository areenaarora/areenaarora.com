Build a visual data story

Look at the page before the code

A visual story is a sequence of decisions.

01 · LeadWhat should I notice first?
02 · EvidenceWhat proves the finding?
03 · ContextWhat keeps it honest?

As we inspect two or three examples, track the reader’s path: headline → evidence → explanation → limits.

Every strong story has an editorial spine

Headline

The finding, stated plainly.

Dek

One sentence that adds meaning.

Byline

Who made it, and when.

Visual

A chart or image that earns its space.

Caption

What to look for, plus the source.

Method note

How the numbers were made comparable.

Build a rhythm

Claim. Evidence. Explanation.

Paragraph: Start with what changed or who was affected.

chart-1.png · image or chart

Caption: tell readers what to notice. Source: name the dataset. Chart: your name.

After the visual: explain the takeaway in words; do not make the reader decode the chart alone.

Use rules to create hierarchy.

body { background: #f7f3eb; } h1 { font-size: 5rem; line-height: .95; } .dek { max-width: 620px; } figure img { width: 100%; }
Type

Large serif headline. Quiet sans-serif labels.

Space

Let sections breathe. Resist filling every gap.

Accent

Use red once to direct attention.

A polished page still explains its limits.

Methodology note

Say where the data came from, what period it covers, how you cleaned it, and what it cannot show.

Alt text

Describe the chart’s takeaway, not just “image of chart.”

Use semantic HTML, sufficient contrast, visible focus states and captions that make sense without the image.

Does the page answer one question clearly?

Read aloud

Can someone find the main point in five seconds?

Check mobile

Does the layout still work on a narrow screen?

Check links

Do the source and analysis links open?

The best visual story is not the busiest one. It is the one a reader can trust.

data story webpage.

  1. Choose one defensible finding.
  2. Write a headline, dek and byline.
  3. Add one chart or image with alt text and caption.
  4. Include a methodology note and source link.
  5. Publish or save a shareable preview.
